## 5. จุดสำคัญและเทคนิคที่ใช้

### 5.1 ตัวสะสมค่า (Accumulator) — แบบบวก vs แบบคูณ
นี่คือหัวใจของข้อนี้ตามโน้ตของผู้ออกโจทย์ **ค่าเริ่มต้นของตัวสะสมต่างกัน**:

| แบบ | ค่าเริ่มต้น | เหตุผล |
| :--- | :---: | :--- |
| สะสมแบบ **บวก** (sum) | `0` | 0 เป็นเอกลักษณ์การบวก — บวก 0 ไม่เปลี่ยนค่า |
| สะสมแบบ **คูณ** (product) | `1` | 1 เป็นเอกลักษณ์การคูณ — คูณ 1 ไม่เปลี่ยนค่า |

> ถ้าเผลอเริ่มตัวสะสมแบบคูณที่ `0` ผลลัพธ์จะเป็น `0` ตลอดไป เพราะอะไรคูณ 0 ก็ได้ 0

```python
result = 1
for i in range(2, n + 1):
    result *= i
```

### 5.2 ทำไมเริ่มลูปที่ 2 ไม่ใช่ 1
`result` เริ่มที่ `1` อยู่แล้ว การคูณด้วย `1` ในรอบแรกไม่ได้เปลี่ยนอะไรเลย
เริ่มที่ `2` จึงประหยัดไป 1 รอบ และสื่อความหมายชัดกว่า

เขียน `range(1, n + 1)` ก็ได้ผลลัพธ์เท่ากันเป๊ะ ไม่ผิด — แค่ทำงานเกินมา 1 รอบเท่านั้น

### 5.3 ทำไม `n = 0` และ `n = 1` ได้คำตอบถูกโดยอัตโนมัติ
- `n = 0` → `range(2, 1)` เป็นช่วงว่าง ลูปไม่ทำงานเลย → `result` คงเป็น `1` ✅ (ตรงกับนิยาม $0! = 1$)
- `n = 1` → `range(2, 2)` เป็นช่วงว่างเช่นกัน → `result` คงเป็น `1` ✅

**ไม่ต้องเขียน `if` ดักกรณีพิเศษเลย** — การเลือกค่าเริ่มต้นที่ถูกต้องจัดการให้หมดแล้ว นี่คือความสวยงามของ accumulator pattern

### 5.4 Python คำนวณเลขใหญ่ได้ไม่จำกัด
`12!` = 479,001,600 ซึ่งเกินขอบเขต `int` 32 บิตของภาษา C/Java ไปแล้ว
แต่ `int` ของ Python ขยายขนาดได้อัตโนมัติตามค่าที่เก็บ จึงไม่ต้องกังวลเรื่อง overflow แม้จะคำนวณ `100!` ก็ตาม

### 5.5 ทางเลือกจากไลบรารีมาตรฐาน
```python
import math
print(math.factorial(n))
```
ใช้ได้และเร็วกว่า แต่ **ข้อนี้ตั้งใจให้ฝึกเขียนลูปเอง** ตามโน้ตของผู้ออกโจทย์ ควรเขียนลูปเพื่อให้เข้าใจกลไก
