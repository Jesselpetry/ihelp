# มาตรฐาน "ภาพรวมรายวิชา" (`summary.md`)

เอกสารนี้กำหนดว่าไฟล์ `content/courses/<dir>/summary.md` ของ**ทุกวิชา**ต้องมีหน้าตาเหมือนกัน
ไฟล์นี้คือสิ่งที่นักศึกษาเห็นในการ์ด **ภาพรวมรายวิชา** บนหน้ารายวิชา และในโมดูล
"เข้าใจวิชานี้ใน 3 นาที" / "คู่มือทบทวน" ของวิชาที่ยังไม่มีคู่มือแยก

อ่านคู่กับ [`../FILE_STRUCTURE.md`](../FILE_STRUCTURE.md) §5 และ
[`LEARNING_BLUEPRINT.md`](./LEARNING_BLUEPRINT.md) — แม่แบบพร้อมใช้อยู่ที่
[`templates/course-summary.md`](./templates/course-summary.md) และ
[`templates/course-blueprint.md`](./templates/course-blueprint.md)

> **ตรวจด้วยเครื่อง** — `bun run content:check` ตรวจหัวข้อ ลำดับ frontmatter และห้ามมี path
> ภายใน repo ในไฟล์นี้ (กฎ `overview-*` ใน [`../scripts/validate-content.ts`](../scripts/validate-content.ts))

---

## 1. หลักการ

1. **เขียนให้นักศึกษาอ่าน ไม่ใช่ให้คนทำเว็บอ่าน** — ห้ามมี path ในเครื่อง (`public/…`, `kmitl-archive/…`,
   `data/…`) สัดส่วนคลังข้อสอบ หรือแผนการสร้างสื่อ สิ่งเหล่านี้ย้ายไป `blueprint.md` (ข้อ 4)
2. **หกหัวข้อเดิมทุกวิชา ชื่อเดิม ลำดับเดิม** — นักศึกษาที่อ่านวิชาหนึ่งแล้วต้องหาของในวิชาอื่นเจอทันที
   ถ้าวิชาไหนไม่มีข้อมูลในหัวข้อใด **ให้คงหัวข้อไว้** แล้วเขียนว่ายังไม่มีข้อมูล
3. **ล่าสุดเสมอ** — ข้อมูลภาคเรียนปัจจุบันมาก่อน ข้อมูลปีก่อนใส่ได้แต่ต้องบอกว่าเป็นของปีก่อน
   ทุกไฟล์มี `updated` ใน frontmatter และบรรทัด "อัปเดตล่าสุด" ใต้ชื่อวิชา
4. **ไม่เดา** — อะไรที่ไม่ได้มาจากเอกสารทางการ (สไลด์ ประมวลการสอน OnLearn) ให้กำกับ *ยังไม่ยืนยัน*
5. **สั้นพอจะอ่านจบ** — เป้าหมาย ≤ 350 บรรทัด รายละเอียดเชิงลึกเกินนั้นไปอยู่ในคู่มือทบทวนแยก

## 2. โครงไฟล์

### 2.1 Frontmatter — คีย์และลำดับตายตัว

```yaml
---
code: "06016402"            # รหัสทางการ 8 หลัก (string)
slug: IT-Fundamentals       # ตรงกับ lib/courses/catalog.ts
shortCode: ITF
nameTh: พื้นฐานทางด้านเทคโนโลยีสารสนเทศ
nameEn: Information Technology Fundamentals
credits: "3 (2-2-5)"
year: 1
term: 1
termId: Y1-S1
prerequisites: []
language: th
semester: "1/2569"          # ภาคเรียนที่ข้อมูลเป็นปัจจุบัน · วิชาเทอม 2 ที่ยังไม่เปิด: "2 (ข้อมูลปีก่อน)"
updated: "2026-09-26"       # วันที่แก้เนื้อหาครั้งล่าสุด (ISO)
sources:                    # เอกสารทางการที่ใช้เขียน ไม่ใช่ path ในเครื่อง
  - สไลด์ Lecture 00–11 (OnLearn 1/2569)
---
```

ค่าที่ไม่รู้ให้ใส่ `"ยังไม่ยืนยัน"` แทนการลบคีย์ (เช่น `credits` ของวิชาข้ามคณะ)
ห้ามเพิ่มคีย์อื่น (`category`, `grading`, `judge` …) — ข้อมูลเหล่านั้นอยู่ในตาราง §1

### 2.2 หัวไฟล์

```markdown
# ITF — พื้นฐานทางด้านเทคโนโลยีสารสนเทศ

> วิชานี้เกี่ยวกับอะไร 1–2 ประโยค
>
> **อัปเดตล่าสุด** 26 ก.ย. 2569 · ข้อมูลภาคเรียน 1/2569
```

- H1 = `# <shortCode> — <nameTh>` เท่านั้น
- blockquote แรกคือคำอธิบายสั้น + บรรทัดอัปเดต (วันที่แบบไทย พ.ศ.)

### 2.3 หกหัวข้อ `##` — ชื่อและลำดับบังคับ

| # | หัวข้อ (พิมพ์ตรงตัว) | ใส่อะไร |
|---|---|---|
| 1 | `## 1. ข้อมูลรายวิชา` | ตารางข้อมูลพื้นฐาน · `### คำอธิบายรายวิชา` · `### สัดส่วนคะแนน` · `### วันสำคัญ` (ถ้ามี) |
| 2 | `## 2. ขอบเขตเนื้อหา` | `### 2.1 ขอบเขตสอบกลางภาค (…)` + `### 2.2 ขอบเขตสอบปลายภาค (…)` — วิชาที่ไม่แบ่งใช้ `### 2.1 แผนการเรียน` |
| 3 | `## 3. สรุปเนื้อหารายหัวข้อ` | `### Week 01 — …` / `### บทที่ 1 — …` / `### Unit 1 — …` หนึ่งหัวข้อต่อสัปดาห์/บท |
| 4 | `## 4. สิ่งที่ต้องจำ` | สูตร ตัวเลข ตารางเปรียบเทียบ ศัพท์ที่สับสน — ตารางเดียวหรือหลายตารางก็ได้ |
| 5 | `## 5. การประเมินและเตรียมสอบ` | `### 5.1 รูปแบบการประเมิน` · `### 5.2 หัวข้อที่ออกบ่อย` · `### 5.3 จุดที่มักพลาด` (ถ้ามี) |
| 6 | `## 6. แหล่งเรียนรู้` | ตาราง สื่อ → ลิงก์ในเว็บ (คลังเรียนรู้ คู่มือ แบบฝึก) และช่องทางทางการ (OnLearn/Classroom) |

ห้ามเพิ่ม `##` อื่น เนื้อหาเฉพาะวิชาให้เป็น `###` ใต้หัวข้อที่ใกล้ที่สุด เช่น

| เนื้อหาเฉพาะวิชา | อยู่ใต้ |
|---|---|
| สไลด์สองชุด / สองแทร็ก (ICS) | `## 2` เป็น `### 2.3` |
| แล็บรายสัปดาห์ (ICS, ITF) | คอลัมน์ "แล็บ" ในตาราง `## 2` |
| คลังโจทย์ OJ (PSCP) | `## 6` |
| ชิ้นงานหลัก (CHARM) | `## 5` → `### 5.1` |
| ตารางค่าวิกฤต Z/t (PSTAT) | `## 4` |
| วิชาสองภาค (MFIT พีชคณิต/แคลคูลัส, BFIT คำนวณ/ทฤษฎี) | `## 3` แบ่งด้วยบรรทัดตัวหนา `**ภาค …**` ก่อนหัวข้อ `###` ชุดนั้น |

## 3. กติกาเนื้อหาแต่ละหัวข้อ

### 1. ข้อมูลรายวิชา

ตารางสองคอลัมน์ `หัวข้อ | รายละเอียด` ลำดับแถวตายตัว:

| แถว | ถ้าไม่รู้ |
|---|---|
| รหัสวิชา | — (ต้องมี) |
| ชื่อวิชา (ไทย / อังกฤษ) | — (ต้องมี) |
| หน่วยกิต | — (ต้องมี) |
| ชั้นปี / ภาคเรียน | — (ต้องมี) |
| วิชาบังคับก่อน | "ไม่มี" |
| ผู้สอน (ภาคเรียนล่าสุด) | *ยังไม่ยืนยัน* |
| ตำรา / สื่อหลัก | *ยังไม่ยืนยัน* |
| ช่องทางเรียน | ระบบที่ใช้ (OnLearn, Google Classroom, Edusoft …) และวัน/ห้องถ้ารู้ |

สัดส่วนคะแนนเป็นตาราง `รายการ | สัดส่วน` และบอกที่มาในวงเล็บหัวข้อ เช่น
`### สัดส่วนคะแนน (Lecture 00, 1/2569)` ถ้าไม่มีฉบับทางการให้เขียนว่า *ยังไม่ยืนยัน*

### 2. ขอบเขตเนื้อหา

- ตารางต้องมีคอลัมน์แรกเป็นตัวเลข (`สัปดาห์` / `บท` / `Unit`) และคอลัมน์ที่สองเป็นหัวข้อ —
  `lib/courses/course-chapters.ts` ใช้ตารางแรกใต้ `## 2.` เป็นแหล่งสำรองของรายชื่อบท
- เส้นแบ่งกลางภาค/ปลายภาคต้องตรงกับที่ผู้สอนประกาศ และเป็นเส้นเดียวกับ `scope` ในคลังเรียนรู้
- สัปดาห์ที่ยังไม่เปิดให้ใส่ "(ยังไม่เปิด)" ต่อท้ายหัวข้อ ไม่ต้องใส่คอลัมน์สถานะคลัง

### 3. สรุปเนื้อหารายหัวข้อ

- หนึ่ง `###` ต่อหนึ่งสัปดาห์/บท รูปแบบ `### Week 06 — Operating System` (เลขสองหลัก)
  หรือ `### บทที่ 3 — …` / `### Unit 4 — …` ตามที่วิชานั้นนับ
- วิชาทักษะที่ไม่มีเนื้อหาแยกบท (เช่น FE) ใช้ `###` ตามทักษะได้ แต่บอกไว้ใต้หัวข้อ `## 3`
- bullet สั้น ศัพท์เทคนิคคงภาษาอังกฤษ
- ความถี่ที่ออกสอบ: ⭐ ออกบ่อย · ⭐⭐ ออกบ่อยมาก · ⭐⭐⭐ ออกแทบทุกปี — ใช้เฉพาะที่มีหลักฐาน

### 4. สิ่งที่ต้องจำ

ตาราง `เรื่อง | ค่าที่ต้องจำ` เป็นค่าเริ่มต้น สูตรใช้ KaTeX (`$…$`) ได้

### 5. การประเมินและเตรียมสอบ

- `### 5.1 รูปแบบการประเมิน` — รูปแบบข้อสอบจริง (ถ้ารู้) ชิ้นงาน แล็บ การส่งงาน
- `### 5.2 หัวข้อที่ออกบ่อย` — รายการลำดับเลข ไม่เกิน 10 ข้อ
- `### 5.3 จุดที่มักพลาด` — คู่คำที่สับสน ข้อลวงที่เจอบ่อย (ใส่เมื่อมี)

### 6. แหล่งเรียนรู้

ตาราง `สื่อ | ที่อยู่` ลิงก์เป็น path ของเว็บ เช่น
`[คลังเรียนรู้](/courses/06016402-IT-Fundamentals/library)` — ไม่ใช่ path ของไฟล์ในเครื่อง
ปิดท้ายด้วยหมายเหตุลิขสิทธิ์ถ้าสื่อเป็นของผู้สอน/ผู้จัดพิมพ์

## 4. `blueprint.md` — ส่วนสำหรับคนสร้างสื่อ

`## 4. แหล่งที่มาในคลัง` · `## 5. ช่องว่างข้อมูล` — ดู [แม่แบบ](./templates/course-blueprint.md)
