### 1. การวิเคราะห์ความซับซ้อนของอัลกอริทึม (Big-O Notation)

Big-O Notation ($O$) เป็นเครื่องมือทางคณิตศาสตร์ที่ใช้วัดอัตราการเติบโตของเวลาประมวลผล (Time Complexity) และหน่วยความจำที่ต้องใช้เพิ่ม (Auxiliary Space Complexity) เมื่อขนาดข้อมูลนำเข้า ($N$) มีค่าเพิ่มขึ้นอย่างมหาศาล

$$\text{เร็วที่สุด} \quad O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N) < O(N!) \quad \text{ช้าที่สุด}$$

#### เกณฑ์ประมาณการสำหรับระบบ Grader / OJ (เวลา 1.0 วินาที $\approx 10^7 - 10^8$ Operations)

| ขนาดข้อมูล $N$ ในโจทย์ | ความซับซ้อนสูงสุดที่ยอมรับได้ | อัลกอริทึมที่ควรเลือกใช้ |
|---|---|---|
| $N \le 1,000$ | $O(N^2)$ | ลูปซ้อนสองชั้น, Bubble / Selection / Insertion Sort |
| $N \le 100,000$ | $O(N \log N)$ หรือ $O(N)$ | Merge Sort, Quick Sort, Timsort (`sorted()`), Linear Scan |
| $N \le 10,000,000$ | $O(N)$ หรือ $O(\log N)$ | Binary Search, Math Formula, Hash Table / Set |
| $N \ge 10^{12}$ | $O(\log N)$ หรือ $O(1)$ | คำนวณด้วยสูตรคณิตศาสตร์ตรงๆ หรือ Divide & Conquer |

### 2. เจาะลึกอัลกอริทึมการเรียงลำดับ (Sorting Algorithms)

#### 2.1 Bubble Sort (การเรียงลำดับแบบฟองสบู่)

- **แนวคิด:** เปรียบเทียบข้อมูลคู่ที่อยู่ติดกัน `(a[j], a[j+1])` หากตัวหน้ามากกว่าตัวหลังให้สลับที่กัน (Swap) ข้อมูลตัวที่มากที่สุดจะค่อยๆ "ลอยตัว" ไปอยู่ตำแหน่งท้ายสุดของแถวในแต่ละรอบ
- **การปรับปรุงประสิทธิภาพ (Optimization):** ใช้ตัวแปรสถานะ `swapped = False` หากวนลูปครบหนึ่งรอบแล้วไม่มีการสลับตำแหน่งเลย แสดงว่าข้อมูลเรียงลำดับเสร็จสมบูรณ์แล้ว สามารถ `break` ออกจากลูปได้ทันที

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:
            break
```

#### 2.2 Selection Sort (การเรียงลำดับแบบเลือก)

- **แนวคิด:** แบ่งอาเรย์เป็นฝั่งที่เรียงแล้ว (ด้านซ้าย) และฝั่งที่ยังไม่เรียง (ด้านขวา) ในแต่ละรอบจะ**ค้นหาตัวที่มีค่าน้อยที่สุด**ในฝั่งที่ยังไม่เรียง แล้วนำมาสลับที่ (Swap) กับตำแหน่งหัวแถวของฝั่งที่ยังไม่เรียง
- **จุดเด่น/จุดสังเกต:** การค้นหาค่าน้อยที่สุดจำเป็นต้องตรวจสอบสมาชิกที่เหลือจนครบทุกตัวเสมอ ดังนั้นไม่ว่าข้อมูลจะเรียงมาแล้วหรือไม่ เวลาประมวลผลจึงเป็น $O(N^2)$ ทุกกรณี

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
```

#### 2.3 Insertion Sort (การเรียงลำดับแบบแทรก)

- **แนวคิด:** เหมือนการจัดเรียงไพ่ในมือ ดึงข้อมูลตัวถัดไปมา (เรียกว่า `key`) แล้วนำไปเปรียบเทียบถอยหลังจากขวามาซ้ายในส่วนที่เรียงแล้ว หากตัวที่ตรวจมีค่ามากกว่า `key` ให้เลื่อนตัวนั้นไปทางขวา 1 ช่อง ทำซ้ำจนเจอช่องที่ถูกต้องแล้วแทรก `key` ลงไป
- **จุดเด่น:** มีประสิทธิภาพสูงมากเมื่อข้อมูลเกือบเรียงลำดับอยู่แล้ว (Nearly Sorted) ใช้เวลาเพียง $O(N)$ ในกรณีดีที่สุด และเป็นองค์ประกอบย่อยใน Timsort ของ Python

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
```

#### 2.4 Merge Sort (การเรียงลำดับแบบผสาน)

- **แนวคิด:** ใช้วิธี **Divide and Conquer (แบ่งแยกและเอาชนะ)**
  1. **Divide:** แบ่งอาเรย์ออกเป็น 2 ส่วนเท่าๆ กันซ้ำๆ จนกระทั่งเหลือสมาชิกตัวเดียว (Base Case)
  2. **Conquer:** ทำการเรียงลำดับส่วนย่อยด้วยการเรียกซ้ำ (Recursion)
  3. **Combine (Merge):** ใช้พอยน์เตอร์ 2 ตัวผสานลิสต์ย่อย 2 ชุดที่เรียงแล้วให้กลายเป็นลิสต์ใหญ่ที่เรียงสมบูรณ์
- **ประสิทธิภาพ:** การันตีเวลา $O(N \log N)$ ในทุกกรณี (ทั้ง Best, Average, Worst) แต่ต้องแลกกับการใช้หน่วยความจำเพิ่ม $O(N)$ ในการสร้างลิสต์ชั่วคราวขณะรวมข้อมูล

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # ใช้ <= เพื่อรักษา Stability
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

#### 2.5 Quick Sort (การเรียงลำดับแบบเร็ว)

- **แนวคิด:** ใช้ Divide and Conquer โดยเลือกสมาชิก 1 ตัวเป็นตัวหลักเรียกว่า **Pivot** แล้วจัดระเบียบข้อมูล (Partition) ให้สมาชิกที่มีค่าน้อยกว่าหรือเท่ากับ Pivot ไปอยู่ฝั่งซ้าย และสมาชิกที่มากกว่าไปอยู่ฝั่งขวา จากนั้นเรียกฟังก์ชันเรียงลำดับฝั่งซ้ายและขวาซ้ำ
- **ข้อควรระวัง:** กรณีแย่ที่สุด (Worst Case) เกิดขึ้นเมื่อเลือก Pivot ได้แย่ เช่น ข้อมูลเรียงลำดับมาอยู่แล้วและเลือกตัวแรกสุดเป็น Pivot ทำให้แบ่งได้กิ่งขนาด $0$ กับ $N-1$ ส่งผลให้เวลากลายเป็น $O(N^2)$

### 3. ตารางสรุปเปรียบเทียบอัลกอริทึมการเรียงลำดับทั้ง 5 ชนิด

| อัลกอริทึม | Best Time | Average Time | Worst Time | Space | Stable? (เสถียรไหม) | พฤติกรรมเด่น |
|---|:---:|:---:|:---:|:---:|:---:|---|
| **Bubble Sort** | $O(N)$* | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **ใช่ (Stable)** | สลับเฉพาะตัวติดกัน เหมาะกับการเรียนรู้ |
| **Selection Sort** | $O(N^2)$ | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **ไม่เสถียร** | ตรวจหมดทุกตัวเสมอ จำนวนครั้งสลับน้อย |
| **Insertion Sort** | $O(N)$ | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **ใช่ (Stable)** | เร็วที่สุดสำหรับข้อมูลเกือบเรียงแล้ว |
| **Merge Sort** | $O(N \log N)$ | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | **ใช่ (Stable)** | การันตี $N \log N$ เสมอ กินแรมเพิ่ม |
| **Quick Sort** | $O(N \log N)$ | $O(N \log N)$ | $O(N^2)$ | $O(\log N)$ | **ไม่เสถียร** | เร็วที่สุดในทางปฏิบัติเมื่อสุ่ม Pivot |

*\*หมายเหตุ: Bubble Sort ได้ $O(N)$ เมื่อมีการใส่ตัวแปรธง `swapped` เพื่อตรวจสอบการสลับ*

> **นิยาม Stable Sort (ความเสถียร):** อัลกอริทึมจะถือว่าเป็น "Stable" ก็ต่อเมื่อ ข้อมูลสองตัวที่มีค่าเท่ากัน จะยังคงรักษา **ลำดับก่อน-หลังตามข้อมูลดั้งเดิม** ไว้เสมอหลังจากเรียงเสร็จสิ้น

### 4. การแกะรอยสถานะข้อมูลทีละรอบ (Pass-by-Pass Tracing)

*รูปแบบข้อสอบยอดนิยมของภาควิชาคอมพิวเตอร์และสารสนเทศ:*
กำหนดอาเรย์เริ่มต้น: `[29, 10, 14, 37, 13]` มีสมาชิก 5 ตัว

#### 4.1 Bubble Sort (รอบที่ 1–4)

- **รอบที่ 1:** เปรียบเทียบ 29-10 (สลับ) $\rightarrow$ 29-14 (สลับ) $\rightarrow$ 29-37 (ไม่สลับ) $\rightarrow$ 37-13 (สลับ)
  $\rightarrow$ จบスรอบ 1: `[10, 14, 29, 13, 37]` *(37 ถูกดันไปท้ายสุด)*
- **รอบที่ 2:** เปรียบเทียบ 10-14 (ไม่) $\rightarrow$ 14-29 (ไม่) $\rightarrow$ 29-13 (สลับ)
  $\rightarrow$ จบรอบ 2: `[10, 14, 13, 29, 37]` *(29 อยู่ตำแหน่งถูกต้อง)*
- **รอบที่ 3:** เปรียบเทียบ 10-14 (ไม่) $\rightarrow$ 14-13 (สลับ)
  $\rightarrow$ จบรอบ 3: `[10, 13, 14, 29, 37]` *(14 อยู่ตำแหน่งถูกต้อง)*
- **รอบที่ 4:** เปรียบเทียบ 10-13 (ไม่สลับ) $\rightarrow$ จบรอบ 4: `[10, 13, 14, 29, 37]`

#### 4.2 Selection Sort (รอบที่ 1–4)

- **รอบที่ 1:** ค้นหาค่าน้อยสุดใน `[29, 10, 14, 37, 13]` พบ `10` นำมาสลับกับตัวแรก (`29`)
  $\rightarrow$ จบรอบ 1: `[10, 29, 14, 37, 13]`
- **รอบที่ 2:** ค้นหาค่าน้อยสุดใน `[29, 14, 37, 13]` พบ `13` นำมาสลับกับตำแหน่งที่สอง (`29`)
  $\rightarrow$ จบรอบ 2: `[10, 13, 14, 37, 29]`
- **รอบที่ 3:** ค้นหาค่าน้อยสุดใน `[14, 37, 29]` พบ `14` อยู่ที่เดิม สลับกับตัวเอง
  $\rightarrow$ จบรอบ 3: `[10, 13, 14, 37, 29]`
- **รอบที่ 4:** ค้นหาค่าน้อยสุดใน `[37, 29]` พบ `29` นำมาสลับกับ `37`
  $\rightarrow$ จบรอบ 4: `[10, 13, 14, 29, 37]`

#### 4.3 Insertion Sort (รอบที่ 1–4)

- ส่วนที่เรียงแล้วเริ่มต้นมี 1 ตัวคือ `[29]`
- **รอบที่ 1 (แทรก 10):** นำ 10 เปรียบเทียบกับ 29 พบว่าน้อยกว่า เลื่อน 29 ไปขวา แทรก 10 ไว้หน้า
  $\rightarrow$ จบรอบ 1: `[10, 29, 14, 37, 13]`
- **รอบที่ 2 (แทรก 14):** นำ 14 เปรียบเทียบกับ 29 (เลื่อน 29) และ 10 (หยุด) แทรก 14 หลัง 10
  $\rightarrow$ จบรอบ 2: `[10, 14, 29, 37, 13]`
- **รอบที่ 3 (แทรก 37):** นำ 37 เปรียบเทียบกับ 29 พบว่ามากกว่า ไม่ต้องเลื่อนใดๆ
  $\rightarrow$ จบรอบ 3: `[10, 14, 29, 37, 13]`
- **รอบที่ 4 (แทรก 13):** นำ 13 เปรียบเทียบ ถอยผ่าน 37, 29, 14 แทรกหน้า 14
  $\rightarrow$ จบรอบ 4: `[10, 13, 14, 29, 37]`

### 5. อัลกอริทึมการค้นหาข้อมูล (Searching Algorithms)

#### 5.1 Linear Search (การค้นหาเชิงเส้น)

- ตรวจสอบสมาชิกตั้งแต่ตำแหน่งแรกจนถึงตัวสุดท้ายเรียงตามลำดับ
- **ข้อดี:** ใช้กับข้อมูลที่ **ไม่ได้เรียงลำดับ** ได้
- **ประสิทธิภาพ:** $O(N)$ ในกรณีแย่สุดและเฉลี่ย

#### 5.2 Binary Search (การค้นหาแบบทวิภาค)

- **กฎเหล็ก:** ข้อมูล **ต้องเรียงลำดับแล้วเท่านั้น (Sorted Array)**
- **หลักการทำงาน:** ตรวจสอบค่ากึ่งกลาง (`mid`) หากค่าน้อยกว่าเป้าหมายให้ตัดครึ่งซ้ายทิ้ง หากมากกว่าให้ตัดครึ่งขวาทิ้ง ขอบเขตค้นหาจะลดลงครึ่งหนึ่งในทุกๆ รอบ ($N \rightarrow N/2 \rightarrow N/4 \dots$)
- **ประสิทธิภาพ:** ใช้เวลาเพียง $O(\log_2 N)$ (เช่น ข้อมูล $1,000,000$ ตัว ตรวจสอบไม่เกิน $20$ ครั้ง!)

```python
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1
    
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid        # พบข้อมูล คืนตำแหน่ง index
        elif arr[mid] < target:
            low = mid + 1     # ข้อมูลเป้าหมายอยู่ฝั่งขวา
        else:
            high = mid - 1    # ข้อมูลเป้าหมายอยู่ฝั่งซ้าย
            
    return -1                 # ค้นหาไม่พบ
```

### 6. การเรียงลำดับใน Python ในชีวิตจริง (`sort` vs `sorted`)

Python ใช้ฟังก์ชันจัดเรียงที่ชื่อว่า **Timsort** (พัฒนาโดย Tim Peters) ซึ่งเป็นการรวมข้อดีของ Merge Sort และ Insertion Sort เข้าด้วยกัน มีความเสถียร (Stable) และทำงานได้เร็วระดับ $O(N \log N)$

```python
# 1. list.sort(): แก้ไขในตัวแปรเดิมโดยตรง (In-place) คืนค่า None
numbers = [5, 2, 9, 1]
numbers.sort()  # numbers กลายเป็น [1, 2, 5, 9]

# 2. sorted(iterable): ไม่แตะต้องตัวเดิม แต่ส่งคืน List อันใหม่ที่เรียงแล้ว
original = (5, 2, 9, 1)

# 3. การจัดเรียงหลายเงื่อนไขด้วย Custom Key (lambda)
students = [
    {"name": "Anan", "score": 85, "age": 19},
    {"name": "Boonsong", "score": 92, "age": 18},
    {"name": "Chai", "score": 85, "age": 20}
]

# ตัวอย่าง: เรียงตาม score มากไปน้อย (-score) หากคะแนนเท่ากัน เรียงตาม age น้อยไปมาก
students_sorted = sorted(students, key=lambda s: (-s["score"], s["age"]))
```

## จุดที่มักพลาด

1. **นำ Binary Search ไปใช้กับข้อมูลที่ยังไม่ได้เรียงลำดับ**:
   - ผลลัพธ์จะผิดพลาดทันที ต้องมั่นใจว่าข้อมูลผ่านการ `sort()` มาก่อน
2. **ข้อผิดพลาด Off-by-one ใน Binary Search**:
   - การเขียนเงื่อนไขลูป `while low < high` แทนที่จะเป็น `while low <= high` ส่งผลให้ตรวจไม่ถึงสมาชิกตัวสุดท้าย
   - ลืมปรับขอบเขตเป็น `mid + 1` หรือ `mid - 1` อาจทำให้ติดลูปไม่รู้จบ (Infinite Loop)
3. **จำสับสนเรื่องประสิทธิภาพของ Selection Sort**:
   - ข้อสอบมักหลอกว่า Selection Sort ในกรณีที่ข้อมูลเรียงแล้วจะใช้เวลา $O(N)$ ซึ่ง**ผิด** เพราะ Selection Sort ต้องสแกนหาค่าน้อยสุดจนหมดแถวทุกรอบเสมอ จึงใช้เวลา $O(N^2)$ ทุกกรณี
4. **ความเข้าใจผิดเกี่ยวกับผลลัพธ์ของ `list.sort()`**:
   - การเขียน `res = my_list.sort()` จะทำให้ `res` มีค่าเป็น `None` เพราะเมธอดนี้ทำการจัดเรียงในตัวเดิมและไม่คืนค่าออกมา หากต้องการสร้างตัวแปรใหม่ต้องใช้ `res = sorted(my_list)`
5. **การต่อข้อความแบบ `str += ch` ภายในลูปขนาดใหญ่**:
   - String ใน Python เป็น Immutable การต่อสตริงทีละตัวในลูปจะสร้าง Object ใหม่ขึ้นมาทุกรอบ ใช้เวลา $O(N^2)$ ส่งผลให้ติด TLE ให้แก้โดยการนำใส่ List แล้วใช้ `"".join(lst)` ในตอนท้าย ซึ่งใช้เวลาเพียง $O(N)$
